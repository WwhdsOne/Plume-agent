# TUI 流式输出、思考展示与状态文案（G1b.3）

> 用户于 2026-10-08 授权执行本文。本文记录已批准的技术契约；实现、实测证据及局限见 [G1b.3 审核记录](reviews/G1b.3.md)（2026-10-08 审核通过）。G3 需另行授权。
>
> 依据：[第一阶段计划](phase-01-tui-agent.md)、[模型运行时决策 0003](decisions/0003-model-runtime.md)、[现行键位契约](tui-keys.md)、[主题契约](tui-splash.md)。2026-10-07 用户要求先改技术文档，审核后再实现。
>
> 2026-10-08 展示修订：用户消息改用 `>`、助手回答改用 `●`；思考输出默认显示 `Thought`，前置三个小点呈三角排列的旋转动画；标记和标题同列，正文统一左对齐。

## 1. 目标与范围

用户发送消息后立即获得连续的处理反馈，覆盖请求前准备、等待模型、思考内容与答案输出；用户消息以 `>` 开头，助手答案以 `●` 开头并支持基础 Markdown。状态文案可在现有 `config.json` 中定制，默认思考显示文字改为 `Thought`；内部阶段及配置键仍叫 `thinking`。每个模型另有思考强度配置，默认偏好 `high`，可用 `none` 关闭；setup 不新增选择步骤。

本单元包含：SDK 流消费、取消与断流、独立思考事件、按模型能力适配思考强度/关闭、TUI 增量呈现、状态文案配置、基础 Markdown、可复现的离线证据与计量。

本单元不实现检索、长期记忆、技能或工具循环；未来这些工作可以报告实际阶段，但当前不能展示伪造的操作。不开启配置热加载，不切换模型协议，不实现会话跨重启恢复。

## 2. 执行阶段与界面文案

### 2.1 阶段由执行流程报告

应用层接受有效输入并分配 run ID 后立即进入忙碌状态；请求前的实际工作也属于这次 run。空输入、忙碌时重复提交和校验失败不创建新 run。

| 阶段 | 进入依据 | 默认文案候选 | 展示内容 |
| --- | --- | --- | --- |
| `preparing` | run 已接受，正在准备历史和请求 | `getting ready`、`gathering thoughts` | 动画、文案、run 总耗时 |
| `waiting` | 开始模型调用，将请求交给 SDK；尚无有效思考或答案增量 | `waiting`、`brewing`、`connecting dots` | 同上；不表示服务端已经接收请求 |
| `thinking` | 本轮未关闭思考，收到第一个非空思考增量，尚未开始答案 | `Thought` | 三点三角旋转图标 + 思考标题 + 最近 3 行预览 |
| `responding` | 收到第一个非空答案增量 | `responding` | 状态行 + 持续更新的 Markdown 答案 |
| 完成、失败、取消 | 应用层确定唯一 run 终态 | 现有终态标签 | 停止动画和计时，保留最终状态及已有内容 |

一次模型调用通常经过 `preparing → waiting → thinking → responding`，也可以跳过没有发生的阶段。`reasoning_effort: "none"` 经能力校验并按协议关闭后，直接走 `preparing → waiting → responding`，不出现思考预览或空折叠标题。未关闭但模型不返回思考时，也跳过 thinking；配置为 high 不代表已经进入思考阶段，仍须收到实际增量。不能用定时器推测阶段或为展示动画而人为延迟。

同一模型调用已经输出答案后，若协议又返回思考字段，仍保存为思考增量，但状态保持 `responding`，不来回跳动。未来 G3 的再次模型调用可重新经过 waiting/thinking；工具阶段届时使用真实操作名称和结构化事件，不从趣味文案反推执行状态。

### 2.2 状态行与刷新

保留状态栏中的模型、run ID 和已知 usage，忙碌部分示意如下（耗时仅为样式示例）：

```text
⠋ brewing…  2.4s
⠙ Thought…  5.1s
⠚ responding…  6.8s
```

- 使用三个小点呈三角排列的旋转动画，思考期间放在 `Thought` 标题前；可用固定宽度盲文字符帧 `⠋ → ⠙ → ⠚ → ⠓` 循环，每帧恰好 3 个点，靠点位变化表现旋转。它不是实心三角，也不是把省略号 `...` 当作动画；文字保持稳定。准备、等待、回答阶段可复用此活动指示器。主色沿用现有 theme token，无色终端也保留点位动画。
- 动画初始帧间隔为 100ms，与正文 50ms 合并刷新分别管理；动画与折叠控件共用最左侧固定 2 个显示列的槽位（图标及间隔），标题从第 3 列开始。动画帧变化、停止或切换为折叠控件均不改变文字起点。思考结束/首答案到达、失败或取消后立即停止思考图标；无盲文字形或字形无法保持槽位宽度时降级为固定宽度 ASCII spinner，不能让等待逻辑依赖字体支持。验收时记录实际终端的点形和间距。
- 每次进入一个阶段选择一次文案，直到离开该阶段不再随机切换；相邻阶段允许偶然选到相同文字，不要求为了“随机”强制变化。
- 文案只提供文字，动画、省略号与耗时由界面统一添加。窄终端按可见列宽截断文案，优先保留状态和耗时，不使状态栏折行挤压输入区。
- 计时从 run 被接受开始，阶段切换不清零；终态后停止。内部另存模型调用与各阶段时间，不能把准备耗时算成模型推理时间。
- UI 时钟和文案选择可注入测试；动画 tick 不写 trace、不产生模型事件、不阻塞输入。终态立即刷新，不等下一个动画周期。

### 2.3 消息角色标记与统一左对齐

以下是用户指定的排版样例，文字仅用于说明消息样式，不是待回答的游戏数据问题：

```text
  > 是不是几乎所有游戏都没有游玩时间这个值，我记得都是0来着？
    用户消息换行后仍从正文起始列开始。

  ● 这里显示助手回答正文。
    回答换行后也从同一正文起始列开始。
```

- 用户消息用 `>` 替代现有 `You >`，助手答案用 `●` 替代现有 `Plume >`；不重复显示角色名称。最左侧 2 个显示列为图标槽，用户/助手行留空；`>`、`●` 和 `Thought` 的首字符 `T` 统一从第 3 列开始。
- 聊天输出使用固定的“标记/标题列”和“正文列”，所有输出文字左对齐。正文列按统一角色标记槽宽加一个空格计算；`>`、`●`、思考竖线 `│` 均为单列时，用户、答案、思考正文和普通续行都从第 5 列开始。某标记为宽字符时统一扩大角色标记槽，所有正文一起调整，不能逐种角色单独计算起点。
- 标记由 UI 根据消息角色添加，不写入保存的正文、模型上下文或复制用的原始 Markdown。用户首行的 `>` 是角色标记，不进入 Markdown 解析器作为引用语法。
- 每条消息只在首行显示角色标记，后续折行与正文起始列对齐；普通文字、段落和标题均左对齐，表格单元格文字也左对齐。Markdown 列表/代码块的内部语义缩进保留，并以统一正文列为基准。前缀宽度按终端显示单元计算，不能假定 `●` 在所有终端里的宽度一致；Markdown 渲染器不另加外边距或额外段落缩进。
- 用户 `>` 沿用 `themeDark`，助手 `●` 沿用 `themePrimary`，正文仍用正常前景色。未指定的系统提示、错误与输入区键位保持现有约定。
- 思考输出是独立区块，使用 §4 的 `Thought` 标题及动画，不在它前面再加助手答案的 `●`。

## 3. 配置契约

### 3.1 可选的 `tui.status_messages`

在现有配置文件中增加以下可选块。路径继续由 `PLUME_HOME` / 平台回退规则解析，POSIX 默认是 `~/.plume/config.json`。以下片段不能替换完整模型配置：

```json
{
  "tui": {
    "status_messages": {
      "preparing": ["getting ready", "gathering thoughts"],
      "waiting": ["waiting", "brewing", "connecting dots"],
      "thinking": ["Thought"],
      "responding": ["responding"]
    }
  }
}
```

| 情况 | 行为 |
| --- | --- |
| 未提供 `tui`、`status_messages` 或某个阶段 | 该阶段使用 §2 的内置候选 |
| 阶段值为 `null`、空列表或去空白后全为空字符串 | 使用该阶段默认候选；不能靠空列表隐藏状态 |
| 只有一个有效候选 | 固定使用该文字；`thinking` 阶段默认候选 `Thought` 即此情况 |
| 多个有效候选 | 阶段开始时随机选一个；刷新、resize 和思考折叠不重新抽选 |
| 字段类型错误或未知阶段名 | 配置校验失败，英文错误包含准确字段路径，不回显完整配置 |
| 候选包含换行、终端控制字符，或超出限额 | 配置校验失败；每阶段最多 16 项，每项去首尾空白后最多 80 个 Unicode 码点 |

配置支持普通中文、英文和 emoji。文字按字面处理，不做 Shell、环境变量或模板插值；进入 TUI 时继续经过单行净化和可见宽度处理。默认文案为英文，符合现有 CLI 输出约定；用户的自定义语言不受限制。

2026-10-08 仅把 thinking 阶段的默认显示改为 `Thought`，配置键仍是 `tui.status_messages.thinking`。用户已显式配置 `"thinking"` 或其他候选时继续尊重其覆盖；不重写用户文案。角色标记、三点动画和折叠图标由界面管理，不混入候选字符串。

### 3.2 模型级 `reasoning_effort`（默认 high，可关闭）

思考强度影响模型请求，放在 `models[]` 的对应模型项，独立于 `tui.status_messages`。以下片段表示在已有模型项中添加字段；其余 provider、protocol、model 和凭据引用继续保留，不能直接用片段替换完整配置：

```json
{
  "models": [
    {
      "id": "main",
      "reasoning_effort": "high"
    }
  ]
}
```

| 配置值 | 项目语义 |
| --- | --- |
| 字段缺失 | 默认偏好 `high`；保留“来自默认值”信息，用于能力兼容判断 |
| `high` | 显式要求高强度思考 |
| `low` / `medium` / `max` | 显式要求对应强度；由模型能力表确认实际支持或有文档依据的映射 |
| `none` | 显式要求关闭模型思考；通过协议参数控制，UI 跳过 thinking 阶段 |
| 空字符串、`null`、布尔值或其他枚举 | 配置校验失败；错误定位到 `models[i].reasoning_effort`，不将无效值当成关闭 |

使用一个枚举表达强度及关闭，不再增加容易冲突的 `thinking_enabled` 布尔开关。首次 setup 不询问强度；已验证支持的官方 DeepSeek 模型在保存时写入默认 `high`，用户可直接编辑。未验证端点保留缺省，以免落盘 `high` 后被当作显式要求而导致启动失败。重新 setup 同一模型时保留已配置值，尤其不能把 none 重置为 high；切换实际端点/模型后重新校验能力。

**默认偏好和协议支持分开：**

| 模型能力 | 字段缺失（默认 high） | 用户显式设置 |
| --- | --- | --- |
| 已验证支持思考控制与 high | 发送协议所需的启用及 high 参数 | 按能力支持的值发送；不支持的值在发请求前报 `unsupported` |
| 已验证没有思考能力 | 不发思考参数，生效状态为 `unsupported`，正常进行文本聊天 | none 可视为无需额外参数的已关闭；其他强度报 `unsupported` |
| 思考控制能力未验证 | 不盲发参数，沿用供应商默认行为；生效状态为 `unverified/provider_default` | 报 `unsupported` 并说明能力未验证，不能默默忽略用户要求或自动付费探测 |

能力与参数映射按已验证的端点、模型及适配器管理；不能只凭 `openai-compatible`、供应商品牌或模型名子串假定支持。默认 high 是项目偏好，不是对所有兼容端点都能生效的承诺。仅有思考输出能力，也不能推断其可关闭或可调强度。

DeepSeek 首批适配范围限定为已核对的官方端点与当前预设 `deepseek-flash` / `deepseek-v4-pro`，实现时用 fixture 固化请求编码：

- high：发送 `thinking: {"type":"enabled"}` 与 `reasoning_effort: "high"`。
- none：发送 `thinking: {"type":"disabled"}`，省略强度参数，避免同时发送相互冲突的开关与强度。
- low / max：开启思考并发送对应强度；medium 按官方兼容规则映射为 high，同时记录 `requested=medium` / `effective=high`，不能显示为原生 medium。
- 自定义代理、其他模型与其他供应商不自动继承上述能力；后续支持需增加明确映射和 fixture，不升级 SDK 或切换协议来绕过验证。

选择 none 后如果服务端仍返回非空思考字段，视为控制契约不符，终止为 `unsupported`，保留已经显示的答案；不展示 thinking，不自动重发或重新开启思考。接口正常返回且没有思考字段，只能说明客户端按协议请求关闭，不能据此宣称特定的内部计算量或节省比例。

### 3.3 加载、保存与兼容

- 本提案保持 `schema_version: 1`：新增可选显示字段和模型思考强度字段，旧文件仍能读取。支持思考控制的模型默认请求将使用 high，这是用户此次要求的行为变化，不能称为请求行为完全不变。该兼容策略随本文审核，本轮不修改用户文件。
- 在线聊天启动时读取并解析一次；修改配置后下次启动聊天生效。`Ctrl+N` 只新建会话，不重新读配置。
- 无配置文件仍不能启动在线模型；本功能不改变模型/凭据校验。`chat --offline` 继续不读配置，使用内置文案和 fake 脚本；文案/强度配置及 none 路径通过隔离配置、HTTP fixture 与 TUI 注入测试验证。
- `Save` 将四阶段文案写入 `tui.status_messages`；读取旧 schema v1 文件时，首次 `Load` 会原子补齐缺失阶段，并对已验证模型补写 `reasoning_effort: "high"`。保留已有自定义值与未知 JSON 字段，后续读取不重复写入；用户不用重新运行 setup。未验证模型仍缺省 high 偏好，但文件中不写成显式强度要求。
- 新版本中的 setup 重配置和 `Save` 必须保留已提供的 TUI 配置及模型思考强度，继续走既有原子保存流程；失败保留原文件。旧版本程序不知道这些字段，不能承诺降级后重新保存仍保留它们或继续执行 none 语义。
- `config show` 显示四个阶段的生效文案及每个模型的请求强度，标明 `default` / `custom`；本地能力表可确定时显示协议映射结果，否则标明 `unverified`，不发联网探测请求或把 high 偏好显示为已验证生效。保持原有凭据脱敏。setup 不增加文案/思考强度表单，用户直接编辑 JSON。
- 文案仅在启动装配时转为 TUI 自有选项；config 包不依赖 TUI，模型请求、prompt、usage 与业务日志均不携带这些展示文案。
- 思考强度通过 provider/启动装配转为模型层自有的类型化请求选项，由适配器做协议编码；不把供应商 JSON 直接交给 TUI，不通过 prompt 提示词假装关闭思考。Generate 与 Stream 使用相同解析规则。

## 4. 思考内容的展示与保留

### 4.1 与答案分区

只展示供应商接口实际返回的思考字段或明确支持的摘要；不从答案中的 `<think>`、自然语言或等待时长猜测思考过程。没有思考字段或本轮已关闭思考时不出现空思考区；none 下异常返回思考的处理见 §3.2。

默认行为：收到思考时在标题前显示三点三角旋转动画，标题默认 `Thought`，下面展示淡色文字、细竖线和最近 **3 个可见行**；按终端列宽折行后取末尾 3 行，不按网络分片裁切。第一条答案到达后停止该思考动画并收起思考区，答案用 `●` 引出，使用正常前景色及 Markdown 样式。思考区第一版只显示净化后的文本，不额外请求模型生成摘要。

```text
⠋ Thought…  5.1s
  │ ……接口实际返回的思考文本……
  │ ……最近三行预览……

▸ Thought · Ctrl+O to expand
  ● 正在流式输出的答案……
    答案续行与用户、思考正文保持同一左边界。
```

上述两段表示不同阶段，不同时重复显示。`Thought` 的 T 与 §2.3 的 `>`、`●` 同列；图标在左侧独立槽位，思考竖线及正文使用统一的标记列与正文列。活动标题默认 `Thought`，允许由 `status_messages.thinking` 覆盖，覆盖后仍从同一列开始；折叠后的内容类型标签固定为 `Thought`，不受随机文案影响。`▸` 仅表示可展开的静态折叠控件，与运行中的三点三角动画不同。思考标题在可见区域内时由该标题承载本阶段的动画/文案/总耗时，底部状态栏保留模型、run ID、usage，不再重复显示一条同样的思考进度；标题滚出可见区时可由状态栏接续显示。

### 4.2 展开行为

- **Ctrl+O** 切换当前轮的思考详情；空闲时作用于最近一个含思考的回复。经 `KeyMap.ToggleReasoning` 抽象，帮助文本与 runbook 已同步。
- 未收到思考时按下无副作用，不占用输入内容；存在思考时不修改输入草稿、光标或发送消息。
- 用户主动展开后，本轮不再因答案到达而自动收起；再次按键手动收起。新 run 恢复默认“预览 → 自动收起”，不修改已完成消息的折叠选择。
- 第一版不新增历史消息焦点/选择系统，Ctrl+O 不逐条遍历更早回复；先前回复保留自身既有展开状态。更完整的历史消息操作另行设计。
- 按现有 KeyMap 平台约定测试，并确认 textarea 不抢占该绑定；mac/linux 优先，Windows 仍由 G-win 人工验证。

### 4.3 内存、上下文与异常

- 思考文本和答案分别存放；折叠不丢弃内容，也不改变模型是否开启思考。思考不是答案的一部分，不拼接到 `Message.Content`。
- 默认只在进程内保留思考全文，不新增聊天落盘或思考 trace 正文。字节上限包含思考和答案，继续遵守单次流 16 MiB 限制；超限明确失败，不静默截断后报成功。
- 协议数据保留和下一轮请求编码由模型适配器决定，不能由 UI 是否折叠决定。DeepSeek 当前无 tools 请求无需回传思考；携带 tools 的请求要求完整回传。G1b.3 只覆盖无工具路径，G3 必须另加回传 fixture，不能把“当前不用回传”固化为全局丢弃策略。
- 取消或断流时保留已收到的思考和答案，标记 `cancelled` / `incomplete`，停止动画。失败轮次不提交到模型会话历史；重试为新 run，不自动续接。
- 只有思考、没有答案且没有受支持工具结果时，不能把思考当作成功回答；终止后归为 `invalid_response`，保留可见内容并提示 `no answer text`。

## 5. 流事件与职责边界

保持 SDK 负责 SSE 分帧，适配器负责归一化，app/agent 负责执行阶段与 run 终态，TUI 负责展示。模块间只使用项目类型。

| 层 | 拟扩展的内容 | 约束 |
| --- | --- | --- |
| `internal/model` | 独立 `reasoning_delta` / `ReasoningDelta`、思考响应字段和类型化强度/关闭选项 | 与 `text_delta` 分开；区分输出、调强度和关闭能力；Generate/Stream 一致；不暴露 SDK 类型 |
| `internal/model/openai` / `deepseek` | 将已支持协议字段转换为上述事件 | 在已锁定 SDK v1.12.0 下验证扩展字段；未知供应商字段不能未经验证宣称兼容 |
| `internal/agent` | 准备请求、消费拉取式流、汇总完整结果，向调用方报告阶段和增量 | 不渲染文案、不读 TUI 配置；保留取消、finish reason 与错误分类 |
| `internal/app` | 带 run ID 的阶段变化、思考增量、答案增量、usage 和唯一终态 | 有界队列、取消可退出；完整成功后才提交历史 |
| `internal/tui` | 消费结构化事件，选择文案、折叠思考、渲染答案 | 不访问模型 HTTP，不解析日志推断阶段；旧 run 的迟到事件不影响新 run |
| `internal/telemetry` | 阶段耗时、首思考/首答案、取消、终态与计量 | 不因 UI 刷新次数或随机文案改变统计，不默认存思考全文 |

归一化流仍保留 usage、模型结束、流结束/中断等语义。一次 SDK chunk 可以同时带思考与答案；适配器必须分别产出事件，不能用互斥 `else` 丢掉其中一类。空字段和纯 usage 帧不触发 thinking/responding，也不计首内容时间。

模型结束不等于 run 完成；必须消费协议要求的结束证据和可用 usage 尾帧，EOF 不能普遍视为成功。SDK 自动重试继续关闭；成功、失败、取消都必须关闭流，Close 幂等。

增量合并只允许合并同一 run、同一内容类别的相邻文本，保持原顺序；阶段、usage、错误和终态不能被覆盖。终态显示前处理已经接收的增量；背压、取消与 UI 退出不能导致终态死锁或 goroutine 泄漏。流接收和关闭独立于 UI 的 50ms 渲染节流。

## 6. 基础 Markdown 与流式渲染

### 6.1 显示范围

| 内容 | 第一版行为 |
| --- | --- |
| 标题、粗体、列表、引用 | 紧凑的终端样式；标题不添加大面积装饰或多余空行 |
| 行内代码、围栏代码块 | 保留缩进与文本，代码块显示语言（若有），使用克制的语法配色 |
| 链接 | 显示标签及目标地址；首版不生成 OSC 8 终端超链接 |
| 表格 | 按终端宽度显示；过宽时降级为保留全部文字的逐行文本，不横向截掉内容 |
| 图片、HTML、数学公式 | 图片显示替代文字/地址；其余保留可读源文本，不加载远程资源或执行 HTML |

正文使用终端默认前景色，标题/引用等复用现有 theme token。颜色方案集中管理；16/256 色与无色终端都有可读降级，不新建另一套独立品牌配色。

实现锁定 `charm.land/glamour/v2 v2.0.1`，沿用 Lip Gloss v2 生态。适配层补充无 OSC 8、窄表降级、源文净化、代码围栏保护及雾青语法色；具体性能与体积见审核记录，不能用 SDK/渲染器版本代替验收证据。

### 6.2 更新、缓存与滚动

- 内容源保留原始 Markdown，UI 持有净化后的渲染输入；ANSI 样式只是派生显示结果，不写入模型历史。
- 初始合并刷新间隔为 **50ms**，合并期间继续收流与响应按键。已完成回复缓存；只因正文、可见宽度、样式或折叠状态变化重建相关缓存，不随 spinner 重绘整段历史。
- 首个可见答案和终态优先刷新；代码围栏、强调等尚未闭合时也能看到已到达内容。必要的显示层临时补全只能作用于渲染副本，不能回写原文；无法稳定渲染的尾部暂按净化文本显示。
- 渲染失败回退到净化后的纯文本并记录有界错误类别，不能丢掉已经收到的回答。终态再进行一次完整排版，不重复追加全文。
- 用户停留在底部时自动跟随；主动向上滚动后冻结阅读锚点，只有滚回底部才恢复跟随。追加内容、折叠、终态排版和 resize 均不能无故跳到底部。
- 普通段落按终端显示单元换行，不能按 UTF-8 字节切片；中文、emoji、组合字符与 ANSI 宽度一并验证。长代码行可视觉软换行，但保存的代码与缩进不变。
- 待渲染的模型文本在 Markdown 解析前净化控制序列；净化必须覆盖跨增量分片的控制序列，不能逐片处理后让片段重组为指令。渲染器只输出样式需要的控制序列，不允许内容或链接触发剪贴板、光标移动、OSC 或终端查询。

## 7. 计量口径

| 指标 | 起止与缺失值 |
| --- | --- |
| run 总耗时 | 应用层接受输入 → run 唯一终态；包含请求前准备，用于状态行 |
| 准备耗时 | run 开始 → 第一次模型调用开始；前置失败时记录实际终止耗时 |
| 模型首思考延迟 | 模型调用开始 → 首个有效思考增量；没有思考时 N/A |
| 模型首答案延迟 | 模型调用开始 → 首个有效答案增量；对应原“模型首文本”，思考/usage/动画均不计入 |
| TUI 首答案延迟 | 接受输入 → 首个可见答案写入渲染帧；对应原“TUI 首文本”，不把 thinking 预览算答案 |
| TUI 完成与取消耗时 | 保持第一阶段指标字典；模型调用与 UI 绘制分别报告 |

思考内容在客户端出现的时间区间不等于模型内部推理耗时，不显示推算的“真实思考时长”。网络 chunk、事件个数、字符数均不冒充 token；usage 仅使用供应商实际提供的计量，缺失为 unknown。

trace 记录阶段 ID、run/模型调用关联、时刻、字节计数、终态与错误类别；思考控制记录请求强度、默认/显式来源、适配映射结果及能力状态，未知生效值写 unknown。none 时首思考指标为 N/A，不能当 0。默认不记录自定义文案、思考正文或原始网络数据。协议 fixture 使用人工构造数据，不能把真实用户内容混入离线评测集。

## 9. 验收矩阵与运行方式

以下是批准的验收矩阵；实际执行结果与尚需人工检查项见审核记录。每个关键行为先建立失败测试，再实现；模拟流与时钟控制时序，不依赖真实模型或长时间 sleep。

| 范围 | 必须覆盖的场景与断言 |
| --- | --- |
| 协议 | 跨 chunk/UTF-8、CRLF、多行 data、空 delta、纯 usage、结束标记、畸形 JSON、中途 EOF、16 MiB 超限；正常和异常终态不混淆 |
| 思考归一化 | 无思考、仅思考、先思考后答案、同 chunk 两类内容、答案后思考、扩展字段缺失；两类文本不丢失、不混拼 |
| 思考控制 | 缺省 high、显式 high/none、支持档位与 medium 映射、不支持/未验证能力；断言请求体实际启用/关闭参数，未支持的显式值不发 HTTP；none 下服务端仍返思考明确失败，不自动重试 |
| 一致性 | 同 fixture 的 Generate/Stream 最终答案、思考、finish reason、已知 usage 一致；不重复累计 usage |
| 生命周期 | 请求前取消不发送 HTTP；建连/读流/背压时取消均退出；唯一终态、Close 幂等、旧 run 迟到事件隔离；失败部分不入历史 |
| 状态与文案 | preparing 立即可见、未收思考不进入 thinking；内部键 thinking 与默认显示 Thought 分离、自定义覆盖保留；三角动画每帧 3 点且等宽、思考结束/取消即停、可见区域不重复显示；文案不进入请求 |
| 角色排版 | `>`、`●`、Thought 首字符同列；动画/折叠占固定左槽，状态变化不移动文字；用户/答案/思考正文及普通续行共用左边界；宽字符标记统一补齐、长中文/emoji/resize 后仍对齐，渲染器不二次缩进；标记不进入模型上下文 |
| 配置 | 旧 v1 首次读取原子补齐默认文案及已验证模型的 high，重复读取不改写；文案空/null 回退与强度 null/非法枚举拒绝；类型/阶段/控制符/长度错误；setup 不问强度且保留既有 none，切换模型重新校验；原子保存失败保护、show 脱敏及能力状态；offline 不读配置 |
| 展开与输入 | 默认三行预览、首答案自动收起、手动展开不被覆盖、Ctrl+O 无内容时无副作用；发送/换行/草稿/取消键位不回归 |
| Markdown | 未闭合代码/强调、嵌套列表、宽表、长链接、中文/emoji/组合字符、跨增量分片的控制序列；原文不变、渲染失败纯文本可读 |
| 刷新与滚动 | 合并刷新不丢字、终态不重复追加；主动上滚保持锚点、回底恢复跟随；窄端/resize 不越界、不丢草稿 |
| 计量 | 准备/首思考/首答案各自计时；动画与预览不提前触发首答案；usage 缺失 unknown；默认 trace 不含正文/文案/凭据 |
