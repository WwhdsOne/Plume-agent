# G3 工具循环实施计划

用户于 2026-10-09 授权继续一个阶段并实现 tool 循环，并在 G3.1 审核中通过基础循环。本计划保留初始实施口径，原只读工具和固定预算已被 G3.1 替代，现行行为见[工具契约](../../specs/agent/tools.md)。关联的长期规划为[第一阶段计划](../../plans/phase-01-tui.md)与[上下文规划](../../plans/agent-context.md)。

**Goal：** 实现用户→模型工具调用→串行执行→回传→最终答案的流式与非流式闭环。

**Architecture：** tools 的不可变注册表提供声明、许可与执行；agent 的 PromptBuilder 构造基础规则、完整历史组和 run 轨迹，Runtime 控制预算；model 适配器转换 SDK 字段；app 原子提交完整成功轨迹，TUI 显示脱敏状态。

**Tech Stack：** 已锁定 Go/openai-go/charm.land/zap，不增加外部依赖。

执行方式：在原目录逐项使用 executing-plans 与 TDD；沿用用户要求，不创建 worktree。2026-10-09 用户审核通过 G3.1 及其基础 G3 循环并授权提交推送；后续单元不自动推进。

- [x] 保留流式 index/ID 稳定性检查，测试分片参数、冲突、截断及 finish_reason 一致性。

## 2. 注册表与只读工具

- [x] internal/tools/{registry,calculator,clock}.go 与 registry_test.go：稳定排序、重名拒绝、未知名称结构化错误、严格参数（拒绝未知键、重复键、缺项、非法枚举与非有限数字）。
- [x] calculate 参数为 operation:add/subtract/multiply/divide 与 a/b 数字；除零和溢出返回错误；current_time 参数为空对象，输出注入时钟的 UTC RFC3339 时间。
- [x] `rtk go test ./internal/tools` 验证失败后最小实现，再通过。无 Shell、网络或文件工具。

## 3. Agent 拼装与循环

- [x] internal/agent/{prompt,budget,loop}.go：基础规则 plume-tools-v1 仅一份；声明来自同一注册表；深拷贝历史；生成前校验完整工具组；默认 1 MiB 请求字节上限，32 KiB 单调用参数，8 KiB 结果上限。
- [x] 必要消息组超限明确失败，不静默裁剪已提交历史（沿用首版无隐式删历史）；工具超长结果以结构化 truncated 标记返回。
- [x] Runtime.Run/RunStream 使用同一循环，默认 8 模型/8 工具、180s run、120s 模型、5s 工具；整批预检模型续调及工具预算，未完成/截断/ID 冲突不执行，未知工具或参数错误回传模型纠正。
- [x] tools_test.go 先验证原实现返回 unsupported；再实现，覆盖串行多个工具、错误纠正、重复 ID 不重跑、预算、超时、取消、普通文本不触发工具及 Generate/Stream 一致性。

## 4. app、trace 与 TUI

- [x] Session.AppendTurn 原子提交 user/assistant-tool/tool/final 消息组；失败/取消不提交；历史副本的 ToolCalls 不共享。
- [x] 每次模型调用使用独立 ID，usage 更新/终态替换同一 ID，ctx 使用最近调用而 cache 累计所有实际调用。
- [x] telemetry/agent.go 记录请求摘要（规则版本、哈希、长度、声明与 schema 版本）、工具验证/开始/终态与耗时；不写参数、结果、思考或 prompt 正文，不记录未知工具的原始名字。
- [x] TUI 使用既有系统行展示工具名、状态与有界安全摘要，保持正文左对齐、取消和滚动行为；新阶段等待可以在工具后再次出现。
- [x] CLI 的在线/离线装配启用内置工具；离线演示通过明确 `/demo calculate`、`/demo time`、`/demo error` 指令，不冒充模型智能选择。
