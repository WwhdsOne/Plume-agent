## 构建脚本与版本注入（同日）

用户提出：`herald version` 打的是 Go 工具链版本，装到 PATH 后无法判断二进制来自哪次构建。

新增：

- `VERSION`（仓库根，当前 `0.1.0`）——人工维护的语义版本。选它而非 git tag 驱动，因为仓库 **0 个 tag**，`git describe --tags` 直接失败。
- `cmd/herald/version.go` —— `version` / `commit` / `buildTime` 三个变量，默认 `dev` / `none` / `unknown`，由 ldflags 注入；未打戳时如实显示，不伪造版本号。
- `scripts/build.sh` —— 读 `VERSION` + `git rev-parse --short HEAD`（脏则加 `-dirty`）+ UTC 时间，注入后构建；支持 `-o/--output`、`--install`（写到 GOBIN）、`--debug`（不剥离符号）、`-h`。

实测：打戳产出 6,751,906 B（`-s -w`），裸构建 9,747,010 B；`./scripts/build.sh --install` 用临时 GOBIN 验证通过，未触碰真实 `/Users/go/bin`。

发现：`/Users/go/bin/herald` 已存在（13:25，9,746,850 B，输出旧格式 `herald-agent (go1.27.1)`），是加版本注入**之前**的裸构建产物。已提醒用户用脚本重装。

## G1b.1 实现：OpenAI SDK 非流式模型接口（同日）

- **依赖**：引入 `github.com/openai/openai-go` v1.12.0（同参数 `-s -w` 实测增量 +1.70 MB：6.41→8.11 MB）。传输层二次决策（Resty→SDK）落地为代码。
- **新包**：`internal/model`（契约/错误 11 类/能力三态/fake）、`internal/model/endpoint`（URL 安全、禁重定向、禁自动重试、8 MiB 预检、空 key 删鉴权头）、`internal/model/openai`（Chat Completions 适配器：单候选校验、usage 存在性、apierror 分类、request ID）、`internal/model/deepseek`（组合兼容实现）。`internal/provider` 增加 ModelFactory/ModelSpec/Probe（ModelSpec 刻意不引用 config，保持 provider 零依赖——config 的测试以本包做替身，直接 import 会成 import cycle）。`internal/telemetry` 增加 ModelRecorder（start + 唯一终态、usage_known 表达缺失）。`internal/eval` 新建（数据集 runner）。
- **关键实现发现 1**：net/http 的 ctx 取消只对裸 `*http.Transport` 生效——经自定义 RoundTripper 包装后取消会静默失效（请求继续到自然结束）。endpoint 因此用显式 `*http.Transport` + `option.WithMiddleware` 做 Content-Length 预检，不用包装 RoundTripper。
- **关键实现发现 2**：SDK 中间件层取消不保证立即关闭底层连接（服务端感知不到断开）。测试以 release 通道兜底，不依赖该时序；G1b.3 流式的关闭语义需重新验证。同时 SDK 严格校验响应 Content-Type（非 application/json 拒绝解析），这正好支撑"非 JSON 响应 → invalid_response"的分类。
- **测试**：新增 34 个测试（model 3、endpoint 8、openai 14、deepseek 2、provider 4、telemetry 4、eval 2）；`go test ./...`、`go test -race ./...` 全绿（11 包）；vet/gofmt 干净。
- **显式联网 probe**（用户当日提供测试 key，仅此一次真实调用，key 不入仓库）：deepseek-chat 经 DeepSeek 适配器请求闭环成功——finish=stop、content="pong"、usage 12/2/14、耗时 6.092s（单次样本，非性能基线）。测试无环境变量即 skip。
